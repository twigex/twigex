Guidance for AI coding agents working in this repository. It adds to the
documents written for people and does not replace them. If this file disagrees
with any of them, they take precedence and this file should be corrected.

- [`CONTRIBUTING.md`](CONTRIBUTING.md): how to contribute, security reporting,
  contribution terms. In particular
  [AI-assisted contributions](CONTRIBUTING.md#ai-assisted-contributions), which
  governs the work you are doing.
- [`docs/development/backend.md`](docs/development/backend.md): Go architecture
  and conventions.
- [`docs/development/frontend.md`](docs/development/frontend.md): Vue 3
  conventions.
- [`docs/development/testing.md`](docs/development/testing.md): test layers,

## The project

Twigex is a self-hosted team collaboration platform providing files, chat,
projects, video and business intelligence. The Go backend is at the repository
root and the Vue 3 frontend is in `frontend/`. The licence is AGPL-3.0-only.

Base your work on `main`, which is the branch all changes merge into.

## Commands

Run these from the repository root. They are the commands CI runs, so a change
that fails here will not merge.

    make lint            lint-go and lint-frontend together
    make lint-go         gofmt and golangci-lint (which includes go vet)
    make lint-frontend   prettier --check and eslint over the frontend
    make test-all        the full suite under -race; requires TEST_MYSQL_DSN
    make test-frontend   npm ci and vitest
    make check-headers   licence headers
    make check-i18n      the four locales carry the same IDs
    make check-tidy      go.mod and go.sum drift
    make check-vuln      govulncheck, filtered to findings this code reaches

To run a single Go test, use `go test ./app/ -run TestName`. To run only the
frontend tests, use `cd frontend && npm test`.

`make test-all` will not start without a database:

    export TEST_MYSQL_DSN='user:pass@tcp(127.0.0.1:3306)/?multiStatements=true'

This refusal is intentional. Without a connection string every store test skips
and the run reports success without having exercised any SQL.

## Constraints

**Licence headers.** Every new `.go`, `.js`, `.css`, `.vue` and `.html` file
begins with the two lines below, written in that language's comment syntax.
Migrations are excluded deliberately. `make check-headers` fails without them.
Note that the check matches on the SPDX line alone, so an incorrect copyright
line will pass CI and still leave the file inconsistent with the rest of the
tree.

    // Copyright (c) 2022 Twigex, SIA.
    // SPDX-License-Identifier: AGPL-3.0-only

**Use `make tidy` rather than `go mod tidy`.** The enterprise import cannot be
resolved without a module this repository does not contain, so the target moves
that file aside and restores it afterwards.

**Migrations.** Write only `.up.sql` files; down migrations are no longer
applied. Never modify a migration that has already shipped. Nothing records a
checksum for them, so an existing installation will not run it again and the
change reaches new installations only. Migrations must run on both MariaDB and
MySQL 8, which excludes `ADD COLUMN IF NOT EXISTS` and a non-null `DEFAULT` on
`TEXT` or `JSON` columns.

**The enterprise boundary.** `enterprise/imports.go` is built under
`//go:build enterprise` and `enterprise/stub.go` under `//go:build !enterprise`.
This repository must build and test successfully with no private module
present. Do not modify either file, and do not add commercially gated behaviour
here.

**Translations.** There are four locales: `en`, `lv`, `kk` and `pl`. A string a
user will read belongs in all four; an internal string may be `en` only. CI
verifies that the IDs match across all four.

## Comments

Write none by default. Add a comment only where the code cannot make the point
on its own, and explain why rather than what. Do not add a comment to a line
that did not already have one. Do not record that code was generated by an AI,
and do not describe the edit being made.

This is the rule broken most often in this repository.

## Formatting

Write code that reads as a sequence of distinct steps, not one dense block,
matching the surrounding code. Passing `gofmt` or Prettier does not make dense
code acceptable. Before you report a change, reread every hunk you added and
break up anything packed.

## Scope

Keep each change to a single concern. Do not reformat unrelated files and do not
carry out refactoring that was not requested. Confirm that a dependency exists
in its registry before adding it.

Ask before adding a dependency, changing the build, writing a migration,
touching authentication, sessions, permissions, cryptography or secret
handling, or letting a change grow beyond a few hundred lines.

Never commit secrets or tokens, and never add code under a licence incompatible
with AGPL-3.0-only.

AI tools are not listed as authors, so commits and pull requests carry no
`Co-authored-by` trailer naming one and no "Generated with" line. An
`Assisted-by: <tool>` trailer is fine.

If an action would breach a rule in this file or in the documents above, stop
and state which rule is at risk rather than continuing without comment.
